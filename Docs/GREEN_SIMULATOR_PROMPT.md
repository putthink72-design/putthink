  # 3D 그린 시뮬레이터 — 게이트 5.5 이전 시각적 사전점검

> 목적: 게이트 5.5(경사로 런처를 이용한 물리적 실측 검증)에 들어가기 전에, 다중브랙 알고리즘이 3D로 눈으로 봤을 때도 물리적으로 그럴듯한지 사람이 직접 확인한다. 동시에 이 화면은 게이트 5.5 실험 실행에 필요했던 "볼·홀 좌표 → 추천 v0/β 표시" 디버그 유틸리티(0-1절)를 3D 버전으로 겸한다. AR·카메라·라이다 실시간 스캔은 이번 범위에 없다 — 번들에 이미 있는 36개 야디지 그린(`.grnh.gz`) 데이터로 완전히 로컬에서 동작하는 정적 시뮬레이션이다.

기존 게이트 2~5 코드(`PuttPhysicsKit`, `TerrainField`, `MultibreakPuttPhysics`, `CandidateSelector`, `GreenHeightmapLoader`, `GreenAligner`)는 변경하지 않는다. 이번 작업은 그 위에 3D 시각화·인터랙션 레이어를 얹는 것뿐이다.

---

## 1. 화면 구성

단일 화면(SwiftUI 뷰 + `SCNView`)으로 구성한다.

1. **그린 선택**: 상단에 드롭다운 또는 리스트로 36개 샘플 그린 중 하나를 고른다 (`manifest.json`의 `id` 목록 사용).
2. **3D 지형 뷰**: 선택된 그린을 3D 메시로 렌더링. 카메라는 기본적으로 비스듬히 내려다보는 각도(퍼팅 시점과 유사)로 시작하되, 사용자가 핀치·드래그로 회전·줌 가능(SceneKit 기본 카메라 컨트롤 사용).
3. **볼/홀 배치**: "볼 놓기" / "홀 놓기" 버튼을 각각 누른 뒤 지형을 탭하면 그 지점에 배치. 재탭하면 위치 갱신(재배치 가능).
4. **추천 정보 패널**: 볼·홀이 모두 놓이면 자동으로 `CandidateSelector`를 호출해 1·2순위를 계산하고 화면에 표시. 접었다 펼치는 상세보기 없이, 아래 값을 **한 화면에 동시에** 계층 구조로 정돈해 보여준다(스크린골프식 안내가 시각적으로 1차 정보, 원시값은 보조 정보로 작게 병기):
   ```
   ┌─ 1순위 ──────────────────────────┐
   │  5.7 m                    +6.4°   │  ← 큰 글씨: 평지환산거리 / 발사각
   │  (+1.5m 오르막 보정)              │  ← 중간 글씨: 보정값
   │  홀이 볼보다 0.12m 높음            │  ← 중간 글씨: 순수 고도차
   │  ─────────────────────────────   │
   │  v0 2.13 m/s · β +6.4°            │  ← 작은 글씨(보조): 원시값
   │  정지위치 (0.08, 3.02) · +0.35m   │  ← 작은 글씨(보조): 오버런
   └────────────────────────────────┘

   ┌─ 2순위 ──────────────────────────┐
   │  5.5 m                    +7.1°   │
   │  (+1.3m 오르막 보정)              │
   │  v0 1.98 m/s · β +7.1°            │
   └────────────────────────────────┘

   후보 없음 시: "반경 완화 재계산 결과 N개 확보" 또는 "후보 없음"
   ```
   구현은 SwiftUI `VStack`으로 큰 폰트(평지환산거리·발사각) → 중간 폰트(보정값·고도차) → 구분선 → 작은 폰트/보조색(원시값) 순으로 계층화한다. 토글이나 탭 전환은 넣지 않는다 — 전부 상시 노출.
5. **퍼팅 버튼**: 누르면 1순위 궤적을 3D로 애니메이션 재생.

## 4-1. 평지환산거리·고도차 계산 (신규 — 게이트 2 엔진 순방향 재사용)

**목적**: 대부분의 골퍼는 "몇 m/s로 쳐라"보다 "스크린골프처럼 몇 m짜리 평지 퍼팅 세기로 쳐라"는 감각적 안내에 훨씬 익숙하다. 다만 일부 사용자는 원시값(m/s, 순수 고도차)을 그대로 보고 싶어 할 수 있으므로 셋 다 함께 표시한다.

**계산 방법 — 새 물리 로직 불필요, 게이트 2의 `FlatPuttPhysics`를 한 번 순방향 실행하는 것뿐이다**:

1. `CandidateSelector`가 뽑은 1순위 v0를 그대로 가져온다.
2. 같은 그린스피드(`sm`)의 **평지(α=0) 가상 그린**에 그 v0로 볼을 굴렸을 때 정지할 때까지의 이동거리를 계산한다 — 이것이 **평지환산거리**.
3. **보정값** = 평지환산거리 − 볼-홀 직선거리(수평 투영 기준). 오르막이면 양수(+), 내리막이면 음수(−)로 표시한다.
4. **순수 고도차** = 홀 위치의 지형고도 − 볼 위치의 지형고도 (`TerrainField.height(at:)`를 두 지점에 각각 조회해 빼기만 하면 된다). 홀이 더 높으면 "홀이 볼보다 N m 높음", 낮으면 "낮음"으로 표기.

이 세 값(평지환산, 보정, 고도차) 모두 이미 검증된 함수 호출 조합일 뿐이라 새로운 버그 표면이 거의 없다. 다만 평지환산거리 계산 시 사용하는 `stopVelocity`, `timeFinal` 등 파라미터는 기존 물리엔진과 동일하게 고정한다(별도 튜닝 금지).

## 2. 지형 3D 메시 생성 (`GreenSceneBuilder.swift`)

1. `GreenHeightmapLoader` + `GreenAligner`로 이미 만들어진 로컬 좌표계 높이맵(스무딩 완료본)을 입력으로 받는다.
2. 격자점을 `SCNGeometry`의 정점으로 변환해 삼각망 메시를 만든다. 원본 20cm 격자를 그대로 정점으로 써도 되고(성능 문제없음 — 그린 하나가 최대 약 200×200 격자), 필요시 시각적 완만함을 위해 격자를 그대로 사용하되 버텍스 노멀은 인접 셀로부터 계산해 부드럽게 셰이딩한다.
3. **색상은 경사 크기(`alpha`)로 히트맵 코딩** — 게이트 4의 `TrajectoryOverlayRenderer`가 2D PNG에서 쓰던 색상 스케일을 그대로 재사용해 3D 버텍스 컬러로 적용한다(완만=녹색, 급경사=빨강 등 일관된 팔레트 유지).
4. 결측 셀(라이다 스캔이라면 있을 수 있으나 야디지 데이터는 전부 채워져 있으므로 이번엔 해당 없음 — 다만 코드는 결측 마스크를 받아 구멍을 안 그리는 처리를 해둔다, 추후 라이다 실시간 경로에 재사용하기 위함)

## 3. 탭 → 좌표 변환

1. `SCNView`의 `hitTest`로 탭 지점의 3D 월드좌표를 얻는다.
2. 메시 생성 시 사용한 로컬↔SceneKit 좌표 변환의 역변환을 적용해, 물리엔진이 쓰는 로컬 (x,y) 평면좌표로 되돌린다.
3. 이 좌표를 `TerrainField`에 조회해 유효 영역(결측 아님) 안인지 확인 — 밖이면 배치를 거부하고 안내 표시.

## 4. 추천 계산 및 궤적 애니메이션

1. 볼·홀 좌표가 둘 다 있으면 기존 `CandidateSelector`를 그대로 호출한다(입력·출력 포맷 변경 없음).
2. 1순위 궤적은 이미 `MultibreakPuttPhysics`가 계산 과정에서 만든 `dataPosition`(각 스텝의 (x,y)) 배열을 그대로 재사용한다 — 별도로 다시 계산하지 않는다.
3. **애니메이션 타이밍**: 원본 물리엔진의 `timeDelta=0.01초` 간격을 그대로 따라 재생하면 실제 물리 시간과 동일한 속도로 보인다(보통 1~3초 내외). 처음엔 이 실속도로 재생하고, 필요시 사용자가 "느리게 보기"(예: 0.3배속) 토글을 켤 수 있게 한다 — 디버깅 시 곡선의 세부 변화를 보기엔 느린 재생이 유용하다.
4. 볼 노드를 `dataPosition` 경로를 따라 `SCNAction` 또는 매 프레임 위치 갱신으로 이동시킨다. 높이(z)는 그 시점의 지형고도 + 볼 반지름(약 0.0214m)으로 얹는다.
5. 궤적 전체를 얇은 선(line strip)으로 지형 위에 함께 그려서, 애니메이션이 끝난 뒤에도 지나간 경로가 남아있게 한다.
6. 결과에 따라 시각적 피드백을 다르게 한다: **홀인**(`ballHoleIf=1`) — 볼이 홀 지점에서 살짝 작아지며 사라지는 간단한 연출, **정지**(`ballStopIf=1`, 홀인 아님) — 그 자리에 멈춤, **통과**(`ballPassOverHoleIf=1`) — 궤적 색을 다르게 표시(예: 노란색)해 "홀 반경은 스쳤지만 안 들어감"을 구분되게 한다.

## 5. 확인해야 할 것 (정식 합격 기준이 아니라 "눈으로 보고 이상 없는지" 체크리스트)

이건 게이트 5.5처럼 수치 기록이 목적이 아니라 **육안 sanity check**이 목적이다. 다음을 확인한다:

- [ ] 여러 그린을 바꿔가며 지형이 실제 그린 형태(요철)와 시각적으로 합리적인지
- [ ] 볼을 그린 여러 위치에 놓았을 때, 추천 β가 표시된 경사색(빨간=급경사) 방향으로 자연스럽게 휘어 보이는지 — 즉 궤적이 눈으로 봐도 "내리막 쪽으로 굽는다"는 직관과 맞는지
- [ ] 표고차가 큰 그린(예: `128_001_2_06_4`)에서 궤적이 뚜렷하게 S자 또는 다중 굴곡을 그리는지 — 다중브랙이 실제로 시각화되는지
- [ ] 완만한 그린(예: `128_001_2_03_4`)에서 "후보 없음 → 반경 완화" 케이스가 발생했을 때, 그 상황을 화면이 명확히 알려주는지
- [ ] 같은 볼·홀 조합을 게이트 5의 자동화 테스트 픽스처와 같은 좌표로 넣었을 때, 화면에 표시되는 v0/β가 테스트 기댓값과 일치하는지 (교차검증)
- [ ] 볼을 재배치하거나 그린을 바꿔도 크래시 없이 상태가 정상적으로 갱신되는지

이 체크리스트에서 뭔가 눈에 띄게 이상하면(예: 궤적이 오르막 쪽으로 휜다, β 표시가 갑자기 반대 부호로 나온다) — **게이트 5.5의 물리적 실험으로 넘어가기 전에 먼저 여기서 잡아야 한다.** 실측 실험은 준비·실행 비용이 훨씬 크므로, 눈으로 잡을 수 있는 버그를 여기서 거르는 게 순서상 맞다.

## 6. 시작 지시

1. 지형 3D 렌더링(2절)부터 구현하고, 그린 하나를 로드해 화면에 그려지는지 먼저 확인한다.
2. 탭 인터랙션(3절)과 추천 계산 연결(4절 1~2)을 붙인다.
3. 애니메이션(4절 3~6)을 마지막에 붙인다.
4. 5절 체크리스트를 스스로 실행해보고 결과를 보고한다 — 특히 "궤적이 경사색과 방향이 맞는지"는 그린 최소 3개(완만/중간/급경사)에서 스크린샷과 함께 보고한다.
